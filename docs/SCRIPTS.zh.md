# 话术与知识库新手教程

面向**开店老板 / 客服**，不会写代码也能改。  
装 Bot、拿 Token、填群 id → 先看 [SETUP.zh.md](./SETUP.zh.md)。本文只讲：**怎么让 Jev 更会帮你回客户**。

---

## 一分钟搞懂两样东西

| 文件 | 叫什么 | 适合放什么 | Jev 怎么用 |
|------|--------|------------|------------|
| `data/scripts.json` | **固定话术表** | 常见问答：营业时间、运费、退换货……关键词对上就出标准答案 | **优先**匹配；命中多条时按相关程度排序 |
| `data/knowledge.md` | **店铺知识库** | 较长说明：店铺简介、售后细则、商品介绍……用标题分段 | 话术没凑满时再补；按文字重合程度排序 |

客户私聊发**文字**后，Jev 会在客服话题里给出建议（**最多 3 条**）：

1. 先从固定话术里挑  
2. 不够再从知识库里补  
3. 客服点「发送① / 发送② / 发送③」，或自己打字回复  

**没有合适的就直接打字**——建议不会自动发给客户。

## 改固定话术（`scripts.json`）

用记事本、VS Code 等打开 `data/scripts.json`。  
整体是一个 **方括号列表** `[ … ]`，里面每一条是一对花括号 `{ … }`。

### 每条有哪些字段

| 字段 | 必填？ | 说明 |
|------|--------|------|
| `id` | 是 | 英文或拼音短名，全表唯一，如 `hours`、`shipping` |
| `keywords` | 是 | 关键词列表。客户话里出现这些词，更容易命中 |
| `question` | 建议有 | 给人看的「典型问法」，也参与匹配 |
| `answer` | 是 | 真正发给客户的完整回复 |

### 安全改法（推荐）

1. **先复制**一条现成的，整段粘贴到列表末尾（最后一条后面、`]` 前面）  
2. 改掉 `id`、`keywords`、`question`、`answer`  
3. 注意：**两条之间用英文逗号 `,` 分隔**；**最后一条后面不要加逗号**  
4. 保存文件 → **重启 Bot**（见下文「改完要做什么」）

### 可直接复制的示例（通用小店）

把下面**整段**插进 `scripts.json` 数组里（注意和前后条目之间的逗号）：

```json
{
  "id": "greeting",
  "keywords": ["你好", "在吗", "您好", "有人吗", "客服"],
  "question": "你好，在吗？",
  "answer": "您好！这里是店铺客服，很高兴为您服务～请问想咨询商品、物流还是售后呢？把问题发给我即可。"
}
```

再来一条「会员 / 优惠」示例：

```json
{
  "id": "member_discount",
  "keywords": ["会员", "优惠", "折扣", "满减", "券", "活动"],
  "question": "有会员优惠或活动吗？",
  "answer": "您好！店铺不定期有满减与优惠券活动，以下单页显示为准。若有专属活动码，可在结算页填写；不清楚也可以把商品名发给我，我帮您看当前优惠～"
}
```

### 常见翻车（保存前看一眼）

| 错误 | 结果 | 正确做法 |
|------|------|----------|
| 最后一条后面多写了 `,` | JSON 读失败，话术可能全部失效 | 最后一条：`}` 后直接 `]` |
| 用了中文引号 `“ ”` | 读失败 | 一律用英文双引号 `"` |
| 两条之间少了 `,` | 读失败 | `},{` 中间要有逗号 |
| `id` 重复 | 难维护，学习入库也可能撞名 | 每条换一个新 `id` |
| `answer` 里写了密码、银行卡、内部链接 | **泄露风险** | 答案只写客户可看的公开信息 |

改完若 Bot 起不来或话术全没了：多半是 JSON 写坏了。用 [jsonlint.com](https://jsonlint.com) 粘贴检查，或从 GitHub 仓库把示例文件重新下载覆盖后再慢慢改。

## 改店铺知识库（`knowledge.md`）

用普通文本编辑器打开 `data/knowledge.md`。  
规则很简单：**一个二级标题 + 下面一段正文**。

```markdown
## 标题写这里

正文写这里。可以多行、列表、简单说明。

## 另一个主题

另一段正文……
```

### 小提示

- 标题用两个井号：`##`（后面空一格再写标题）  
- 客户消息里的词，和标题/正文里的词越接近，越容易被 Jev 选中  
- 适合放「说不完、不适合塞进一句标准话术」的内容  
- **不要**写密码、后台地址、未公开的内部价目

仓库里已有示例：店铺简介、热门商品、售后政策摘要——可直接改成你家的内容。

## 不用改文件：用 `/learn` 学习

适合：**客服已经答过一遍**，想让下次自动建议类似回复。

1. 客户私聊 Bot 发**文字**问题  
2. 客服在对应话题里回复，**或**点 Jev 的「发送①/②/③」，且**成功送到客户**  
3. 管理员**私聊** Bot，发 **`/learn`**  
4. 看到待审核的问答后，点按钮：  
   - **入库话术** → 写入 `scripts.json`（固定问答）  
   - **入库知识** → 写入 `knowledge.md`（长说明）  
   - **忽略** → 不要这条  

入库成功后，一般会**自动热重载**，马上参与下次匹配（通常不必为学习条目单独重启）。

可选：在 `.env` 设置 `LEARN_ADMIN_IDS=`（你的 Telegram user id，可用 `/whoami` 查看），限制谁能审核。

## 改完要做什么？

| 你怎么改的 | 要不要重启 |
|------------|------------|
| 私聊 `/learn` 点「入库话术 / 入库知识」 | **一般不用**，会热重载 |
| 自己用编辑器改了 `scripts.json` 或 `knowledge.md` | **建议重启** Bot（Ctrl+C 停掉，再 `npm run dev` 或 `npm start`） |
| 改了 `.env` | **必须重启** |

生产环境常见：`npm run build && npm start`。

## 迷你 FAQ

**Q：客户问了，话题里没有 💡 建议？**  
- 可能没命中任何关键词 / 知识段落  
- 客户发的是图片、语音等（当前主要对**文字**出建议）  
- `.env` 里 `JEV_ENABLED=0` 关掉了  
- 刚手动改文件还没重启  

**Q：为什么只有 1 条选项，不是 3 条？**  
只找到 1 条够格的匹配就会只显示 1 条。多写几条相关话术、丰富知识库段落，或优化关键词，就更容易凑满。

**Q：怎样让关键词更好用？**  
把客户**常说的原话**写进 `keywords`（口语、错别字常见写法也可以）。例如「几天到」「包邮吗」「退货」。一条里多写几个近义词，比只写一个书面词更稳。

**Q：答案里能写密码、卡号、内部链接吗？**  
**不要。** 点「发送」会原文发给客户。敏感信息只走人工私聊或店内安全渠道。

**Q：三条都不合适怎么办？**  
直接在话题里打字 / 发图回复即可，和没用 Jev 时一样。
